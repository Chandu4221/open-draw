# OpenDraw — Spike Notes (`docs/od-spike-notes.md`)

This document records empirical findings from spikes exploring browser APIs, pointer behaviors, observer edge-cases, or serialization characteristics.
Per OpenDraw working rules: **API facts are spiked, not assumed**. Unfamiliar behavior $\to$ 10-line spike, findings recorded here, spike deleted.

| Spike ID | Date | Target API / Area | Hypothesis & Test | Finding & Conclusion |
|---|---|---|---|---|
| `SPK-001` | 2026-10-20 | DOM Canvas Performance (100–1000 Shapes) | Measured TTFF, per-frame drag block, and pan across 100/500/1000 shapes in Chromium harness (`packages/canvas/e2e/benchmarks.spec.ts`). | TTFF ~30ms, per-frame drag block <0.01ms, pan ~16.6ms at 60fps across all zoom levels (0.2x–5x). DOM retained mode scales without virtualization up to 1,000 shapes. Documented in `docs/od-verification/2/benchmarks.md`. |
| `SPK-002` | 2026-10-20 | DOM Canvas Culling Stress Spike (2,000–10,000 Shapes) | Measured TTFF, per-frame drag blocking, and pan fps at 1× for 2k, 5k, 10k simple shapes in Chromium harness (`packages/canvas/e2e/benchmarks.spec.ts`). | 2,000 shapes (6,002 nodes): TTFF 59.1ms, drag block 0.01ms, 60fps pan. 5,000 shapes (15,002 nodes): TTFF 131.9ms, drag block <0.01ms, 60fps pan. 10,000 shapes (30,002 nodes): TTFF 295.2ms, drag block <0.01ms, 52fps pan. Retention scales well for simple rects; culling trigger is node-per-shape ratio of complex shapes, not raw simple shape count. Documented in `docs/od-verification/2x/culling-stress-results.json`. |
| `SPK-003` | 2026-10-22 | Live-Preview Interaction Baseline (100 Mixed Shapes) | Measured 100-shape baseline across continuous 60Hz drag, resize, rotate, and pan gestures via FrameTelemetry harness (`packages/canvas/e2e/perf-baseline.spec.ts`). | **Drag**: 60fps, p50 11.5ms, p95 13.0ms, p99 13.2ms, 0 dropped frames. **Resize**: 60fps, p50 12.0ms, p95 13.1ms, p99 14.8ms, 0 dropped frames. **Rotate**: 60fps, p50 12.0ms, p95 13.1ms, p99 13.2ms, 0 dropped frames. **Pan**: 60fps, p50 7.8ms, p95 15.5ms, p99 15.7ms, 0 dropped frames. Bottleneck analysis: Main thread JS execution takes ~0.2-0.5ms per event; remaining latency is browser compositor/v-sync scheduling budget (~10-12ms). Transform-only preview mutations bypass DOM reflow/layout entirely. Documented in Phase 2.z §1. |
| `SPK-004` | 2026-10-22 | Cross-Browser Matrix Observations (Chromium, Firefox, WebKit) | Ran 17 Playwright E2E spec suites across browser engines to triage SVG layout, handle scaling, overlay invariants, and serialization differences. | (1) **Empty `<g>` Bounding Box**: An empty SVG `<g class="od-overlay-slot">` in Gecko/Firefox returns viewport origin (0, 0) for `getBoundingClientRect()` rather than CTM origin. Once a child element is mounted into the slot, coordinates track parent transform coherently across all engines. (2) **Stroke Bounding Box**: Firefox computes `getBoundingClientRect()` using the stroke bounding box (8px fill + 1.5px stroke = 9.5px), whereas Chromium uses the fill bounding box (8px). Standardized via `vector-effect="non-scaling-stroke"` so screen stroke thickness remains identical across all zooms. (3) **PNG Serialization**: `editor.exportPNG` generates valid PNG headers (`\x89PNG\r\n\x1a\n`) and distinct byte-accurate chip toggles across both engines. (4) **Compositor Timing**: In headless Linux without hardware vsync, Firefox displays minor synthetic IPC scheduling jitter (~1-2 frames >25ms) while maintaining 60 FPS and p50 latencies <11ms. (5) **WebKit RAF Dispatch vs Synchronous DOM Evaluation**: In WebKitGTK / headless Linux WebKit, synthetic pointer movements dispatch events and schedule `requestAnimationFrame` callbacks asynchronously, but `page.evaluate()` executes on the next microtask before the compositor or animation frame queue has fired. Sampling in-flight mid-gesture DOM mutations in WebKit requires standard double-`requestAnimationFrame` flushing (`flushRAF`) so queued frame callbacks execute before sampling assertions. |
