# OpenDraw — Questions Log (`docs/od-questions.md`)

This document records any open questions, ambiguous specifications, or blockers encountered during development.
Per OpenDraw working rules: **never invent**. Anything unspecified is logged here, marked in code with `// OD-QUESTION:`, and raised with the maintainer.

| ID | Date | Component | Question / Ambiguity | Resolution | Status |
|---|---|---|---|---|---|
| `Q-001` | 2026-10-20 | Canvas Renderer (Culling) | At what shape count threshold should viewport culling (DOM element detachment) be activated? Empirical benchmark SPK-001 indicates that 1,000 shapes (3,002 DOM elements) maintain 60fps pan and <0.01ms drag blocking natively without virtualization. Should culling activate at >= 2,000 shapes or remain deferred until Phase 2.x stress tests? | Culling threshold is measured from SPK-002 data (10k shapes = 30k DOM nodes still yields 52fps pan, <0.01ms drag block, 295ms TTFF). The real trigger for culling is complex shapes' node-per-shape ratio (frames/connectors/ink paths); revisit at first perf regression — not now. Zero culling code written. Evidence: `docs/od-verification/2x/culling-stress-results.json`. | Resolved |
| `Q-002` | 2026-10-20 | Canvas Engine (Parenting) | ADR-002 specifies that a child dragged out of bounds does NOT auto-detach (no continuous recompute), and explicit detach requires user action. What is the explicit detach affordance in v0.x? | Closed in Phase 2.y §5: Implemented gesture re-parenting and detachment. Dragging a shape > 12px screen space outside its parent container detaches it (clearing `meta.parent` and emitting orphan event). Dropping inside a frame container parents it to that frame (smallest-area wins on overlap). Entire re-parent/detach operation is committed in a single undo transaction. Verified in `packages/canvas/e2e/reparent.spec.ts`. | Resolved |
| `Q-004` | 2026-10-22 | Stroke Eraser (Frames vs Children) | When an eraser stroke intersects both a container frame and its children, should the container frame, the children, or both be deleted? | Resolved in Phase 2.y §6: Child shapes take priority. When an eraser stroke intersects a child shape inside a frame, only the child is marked for erasure (`.od-erase-target`) and deleted; the parent frame is spared. If the eraser stroke intersects a frame header or empty area without intersecting any of its children, the frame itself is deleted and any remaining children are cleanly orphaned. Verified in `packages/canvas/e2e/eraser.spec.ts`. | Resolved |
| `Q-003` | 2026-10-20 | Ink Shape (Pressure & Width) | Should pressure sensitivity, variable-width strokes, or velocity-based smoothing be supported in v0.x ink rendering? | Ruling per §6.2: store nothing in v0.x; use constant-width per stroke (`strokeWidth` from props or default 3px / highlighter 20px). Variable width, pressure curves, and tilt are scheduled for a future phase when stylus/Apple Pencil hardware events are integrated. | Resolved |
| `Q-005` | 2026-10-22 | Transform Gestures (Rotation Snapping) | What is the interaction convention for rotation angle snapping vs free rotation during rotate handle drags? | Resolved in Phase 2.z §4: Standardized to the industry convention (Figma / Adobe Illustrator standard): free rotation by default, hold Shift to snap every 15°. Implemented and documented across `computeRotationAngle` options and verified in `packages/canvas/e2e/live-preview.spec.ts`. | Resolved |
