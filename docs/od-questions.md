# OpenDraw — Questions Log (`docs/od-questions.md`)

This document records any open questions, ambiguous specifications, or blockers encountered during development.
Per OpenDraw working rules: **never invent**. Anything unspecified is logged here, marked in code with `// OD-QUESTION:`, and raised with the maintainer.

| ID | Date | Component | Question / Ambiguity | Resolution | Status |
|---|---|---|---|---|---|
| `Q-001` | 2026-10-20 | Canvas Renderer (Culling) | At what shape count threshold should viewport culling (DOM element detachment) be activated? Empirical benchmark SPK-001 indicates that 1,000 shapes (3,002 DOM elements) maintain 60fps pan and <0.01ms drag blocking natively without virtualization. Should culling activate at >= 2,000 shapes or remain deferred until Phase 2.x stress tests? | Culling threshold is measured from SPK-002 data (10k shapes = 30k DOM nodes still yields 52fps pan, <0.01ms drag block, 295ms TTFF). The real trigger for culling is complex shapes' node-per-shape ratio (frames/connectors/ink paths); revisit at first perf regression — not now. Zero culling code written. Evidence: `docs/od-verification/2x/culling-stress-results.json`. | Resolved |
| `Q-002` | 2026-10-20 | Canvas Engine (Parenting) | ADR-002 specifies that a child dragged out of bounds does NOT auto-detach (no continuous recompute), and explicit detach requires user action. What is the explicit detach affordance in v0.x? | Closed in Phase 2.y §5: Implemented gesture re-parenting and detachment. Dragging a shape > 12px screen space outside its parent container detaches it (clearing `meta.parent` and emitting orphan event). Dropping inside a frame container parents it to that frame (smallest-area wins on overlap). Entire re-parent/detach operation is committed in a single undo transaction. Verified in `packages/canvas/e2e/reparent.spec.ts`. | Resolved |
| `Q-004` | 2026-10-22 | Stroke Eraser (Frames vs Children) | When an eraser stroke intersects both a container frame and its children, should the container frame, the children, or both be deleted? | Resolved in Phase 2.y §6: Child shapes take priority. When an eraser stroke intersects a child shape inside a frame, only the child is marked for erasure (`.od-erase-target`) and deleted; the parent frame is spared. If the eraser stroke intersects a frame header or empty area without intersecting any of its children, the frame itself is deleted and any remaining children are cleanly orphaned. Verified in `packages/canvas/e2e/eraser.spec.ts`. | Resolved |
| `Q-003` | 2026-10-20 | Ink Shape (Pressure & Width) | Should pressure sensitivity, variable-width strokes, or velocity-based smoothing be supported in v0.x ink rendering? | Ruling per §6.2: store nothing in v0.x; use constant-width per stroke (`strokeWidth` from props or default 3px / highlighter 20px). Variable width, pressure curves, and tilt are scheduled for a future phase when stylus/Apple Pencil hardware events are integrated. | Resolved |
| `Q-005` | 2026-10-22 | Transform Gestures (Rotation Snapping) | What is the interaction convention for rotation angle snapping vs free rotation during rotate handle drags? | Resolved in Phase 2.z §4: Standardized to the industry convention (Figma / Adobe Illustrator standard): free rotation by default, hold Shift to snap every 15°. Implemented and documented across `computeRotationAngle` options and verified in `packages/canvas/e2e/live-preview.spec.ts`. | Resolved |
| `Q-006` | 2026-10-22 | Canvas Export (Bitmap Context Exemption) | The no-bitmap guardrail forbids getContext in DOM Canvas render paths. How is PNG serialization handled without violating the pure DOM Canvas architecture? | Resolved in Phase 2.s §2: Serializing SVG to PNG is a serialization path, not a canvas rendering path. A strictly audited exemption (`// EXEMPTION: serialization-only path for exportPNG per Phase 2.s §2`) is permitted exclusively in `packages/canvas/src/export/png.ts` for 2D OffscreenCanvas/canvas blitting of the serialized SVG. The live engine render path remains 100% SVG/DOM. | Resolved |
| `Q-007` | 2026-10-23 | Group Transforms & Connectors | How do arrow connectors bound to group members behave during group translation or scaling? | Resolved in Phase 3 §0b: In OpenDraw, arrow connectors are relational bindings (ADR-005) rather than static pixel paths, and group members store absolute world coordinates (ADR-003). When group members are moved or scaled, connector reconciliation automatically resolves dynamic routing to member anchor points without special group-transform overrides. Verified in unit tests and arrow fixtures. | Resolved |
| `Q-008` | 2026-10-23 | Input Repair & Markdown Compiler | Does wheel zoom/pan engine repair alter the frozen `@open-draw/canvas` public API? | Resolved in Phase 4 §0 & §4: No. `PointerInteractionController` attaches standard `{ passive: false }` wheel listeners internally on the mounted container, directly driving existing public camera methods (`camera.zoomAroundPoint`, `camera.pan`). Public API snapshot is unaltered; all guardrails green. `@open-draw/markdown` introduced as private package with pinned golden fixtures. | Resolved |
| `Q-009` | 2026-10-24 | Studio & E2E Tag Panel | Why did clicking inside the tag panel cause selection to clear and the panel to hide, and why did a11y fail in CI? | Root cause: Tag panel was mounted inside canvas-container, causing pointerdown on panel inputs to bubble to canvas engine which interpreted it as empty-canvas click (deselection). Fixed by mounting to document.body with stopPropagation on pointerdown, mousedown, wheel, keydown. A11y axe select-name violation fixed by providing explicit htmlFor and aria-labels, and deduplicating tag panel code between studio and e2e playground. | Resolved |
| `Q-010` | 2026-10-24 | Markdown Compiler (Format v1.1) | How should bounds semantics and spec integrity be codified for consuming LLMs without rigid pixel locking or token desync? | Resolved in Phase 5 §6: Pinned bounds semantics declaration line under version marker: "Bounds are content-size in scene coordinate space. Absolute positions are spatial suggestions, not layout mandates; consuming agents adapt to target platform layout systems." Spec integrity rule: specs are generated artifacts (regenerate, never hand-edit). Future re-import spike must validate name↔token consistency. | Resolved |
| `Q-011` | 2026-10-24 | Markdown Compiler (Untagged & Directives) | How are untagged shapes and AI temperature/fidelity guardrails communicated in Format v1.1? | Resolved in Phase 5 §6: Untagged elements compile as `[untagged:<type>]` in tree and `<type> *untagged*` in legend, with top-level warning banner. Consumption directives (`strict-fidelity` vs `creative-allowed`) explicitly dictate AI liberty. | Resolved |
| `Q-012` | 2026-10-24 | Markdown Compiler (Selection Compile) | When compiling with `shapeIds`, how are unselected children and unparented shapes handled? | Resolved in Phase 5 §7: Unselected children are omitted completely from the output with no warning. Shapes whose parent is not in `shapeIds` compile as tree roots in the Screen Structure; hierarchy among selected shapes is preserved. | Resolved |
| `Q-013` | 2026-10-24 | Markdown Compiler (Selection Scope) | How does selection compile determine the Scope declaration? | Resolved in Phase 5 §7: If the selection contains a shape of semantic type `page`, emit `> **Scope: page**`; otherwise emit `> **Scope: component**`. Directives, responsive behavior, untagged warnings, and legend are computed strictly for the selected sub-scene. | Resolved |
| `Q-014` | 2026-10-24 | Canvas & Studio (Grow-On-Assign) | When a child is assigned to a parent frame that does not contain it, how should frame growth behave? | Resolved in Phase 5 §7: The frame auto-grows to the exact union of parent and child bounds (`minX, minY, maxX - minX, maxY - minY`) with 0px extra padding. Growth cascades up ancestor frames. Groups never clip and never auto-grow. Growth occurs only at assignment time (inspector or gesture drop); subsequent drags within the frame stay clipped. The resize and reparent commit in a single atomic store transaction (single undo step). | Resolved |
| `Q-015` | 2026-10-24 | Studio Inspector (Responsive Readout) | Which shapes should display the live Responsive Readout in the inspector? | Resolved in Phase 5 §7: Only container shapes (`card`, `section`, `column`, `page`, `group`, `frame`, `row`) show the responsive readout. Leaf shapes do not own layout reflow decisions and do not show a readout. Readout text matches the compiler's Responsive Behavior section by calling `derive()` with platform profile breakpoints. | Resolved |
